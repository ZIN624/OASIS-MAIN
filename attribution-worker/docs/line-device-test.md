# LINE 実機テストの手順書（OASIS本店・広告帰属）

自動テストでは確かめられない「LINE の中で、入口ページと予約フォームが**同じ人**として結びつくか」を、スマホで確かめる手順です。

**本番の予約フォーム・本番の公式アカウントのトーク・リッチメニュー・Wix・Google 広告・本番の Worker には触りません。**
テスト用の LIFF とステージングの Worker を使い、テストの予約希望は**テスト用のグループトーク**にだけ届きます。

所要時間の目安: 読み取りの確認 15分 → 準備 60分（承認が要る作業あり）→ テスト 40分 → 数日後の確認 10分。

---

## 0. この手順でしないこと

- 本番の LIFF（`2006621786-8K7V4W3M`）の設定を変えない（エンドポイント・Scope・サイズ・友だち追加オプション）
- 公式アカウント @nlx8658m のリッチメニュー・あいさつメッセージ・応答設定・Webhook を変えない
- 公式アカウントから**配信しない**（お客様には何も届かない）
- 本番の予約フォーム（GitHub Pages）を変えない。PR #7 はマージしない
- Google 広告・Google Cloud・Wix には触らない。Google には何も送らない

## 2. 誤送信・通知を防ぐ方法

| 起きうること | 防ぎ方 |
|---|---|
| テストの予約希望が、公式アカウントのトークに届いてスタッフが予約と思う | **公式アカウントのトークからフォームを開かない。** テスト用のグループトークから開く（下の 2-1）。LIFF の送信は「開いたトーク」に届く仕様のため、公式アカウントには届かない |
| お客様に何かが届く | 配信・リッチメニュー・あいさつメッセージは変えない。テスト用の LIFF の URL はテストする人にしか渡さない |
| 友だち追加のあいさつメッセージ | テストする人のアカウントにだけ届く（お客様には届かない）。友だち数が1増える |
| 本番の解析（GA4・Clarity）にテストの閲覧が混ざる | テスト用ページの写しから GA4 と Clarity のタグを**消す**（3-2） |
| スマホに残っている、本番フォームのお客様情報（名前・電話）が上書きされる | テスト用ページは別のアドレスなので、本番フォームの保存内容とは混ざらない |
| Google 広告に送ってしまう | ステージングは `UPLOAD_ENABLED=false`、Google の鍵も入れない |
| 本番の Worker が動く | 本番の Worker・D1 はまだ作らない |

### 2-1. テスト用のグループトークを作る（オーナー）

1. LINE で、テストする人だけのグループを作る（例: 「OASIS テスト」。オーナーとスタッフ1人など）
2. 予約フォームのテストは、**このグループに貼ったリンク**から開く
3. 送信した予約希望はこのグループにだけ届く

> 本番と同じ「公式アカウントのトークから開く」動きも最後に1回だけ確かめたい場合は、スタッフに事前に伝え、名前「テスト」・備考「テスト送信です」で行います（任意）。

## 3. ステージングの構成（本番と混ぜない）

### 3-1. 本番とステージングの対応

| | 本番（今回は作らない・変えない） | ステージング（テスト用） |
|---|---|---|
| Worker | `oasis-honten-attribution` | `oasis-honten-attribution-staging` |
| D1 | `oasis-honten-attribution` | `oasis-honten-attribution-staging` |
| 秘密の値（`ATTR_ROOT_KEY`・`ADMIN_TOKEN`） | 本番用 | **本番とは別の値**（同じ人でも本番とハッシュが一致しない） |
| Google の鍵（`GOOGLE_SA_KEY_JSON`） | あとで入れる | **入れない** |
| `UPLOAD_ENABLED` | false | **false** |
| `AD_ATTR_ENABLED` | false | テストのあいだだけ true |
| `FORM_ORIGINS` | `https://zin624.github.io` | **テスト用ページのアドレスだけ**（本番のページからは呼べない） |
| `AD_CLICK_ORIGINS` | Wix のアドレス | **テスト用ページのアドレスだけ**（テストの広告クリックはこちらから作る） |
| `LINE_CHANNEL_IDS` | 本番フォームのチャネルID | **同じチャネルID**（同じ人のIDを得るために必要。チャネルは共有するが、LIFF は別） |
| 予約フォームのページ | GitHub Pages（`zin624.github.io/OASIS-MAIN/`） | テスト用ページ（Cloudflare Pages など・別のアドレス） |
| 予約フォームの LIFF | `2006621786-8K7V4W3M`（変えない） | 新しく「STG-フォーム」 |
| 入口の LIFF | （まだ無い） | 新しく「STG-入口」 |
| 解析タグ | GA4・Clarity あり（変えない） | **消す** |

### 3-2. テスト用ページの写しで書き換えるもの

本番のファイルは変えず、**写しだけ**を書き換えます。`scripts/build-staging-site.mjs` が次の4つを行い、
本番の LIFF ID・解析タグが残っていないことを確かめてから写しを作ります（本番の LIFF ID や本番の Worker を指定すると止まる）。

```bash
node attribution-worker/scripts/build-staging-site.mjs --out dist-staging-site \
  --form-liff <STG-フォームの LIFF ID> --entry-liff <STG-入口の LIFF ID> \
  --endpoint https://oasis-honten-attribution-staging.<workers.dev のサブドメイン>.workers.dev
```

1. `js/liff-init.js` の LIFF ID → 「STG-フォーム」の LIFF ID
2. `js/attribution-config.js` の `endpoint` → ステージングの Worker の URL、`entryLiffId` → 「STG-入口」の LIFF ID
3. `index.html` から、GA4（`googletagmanager.com` と `gtag(...)`）と Clarity（`clarity.ms`）のタグを消す
4. `index.html` と `entry.html` の `<title>` の先頭に「【テスト】」を付ける（本番と見分けるため）

### 3-3. 混ざっていないことの確認（テストの前に Claude Code が確かめる）

- [ ] 本番の GitHub Pages の `js/attribution-config.js` の `endpoint` が空のまま（PR #7 がマージされていない）
- [ ] 本番の Worker・D1 が存在しない
- [ ] ステージングの `FORM_ORIGINS`・`AD_CLICK_ORIGINS` がテスト用ページのアドレスだけ
- [ ] ステージングの `UPLOAD_ENABLED=false`、`GOOGLE_SA_KEY_JSON` が無い
- [ ] テスト用ページに GA4・Clarity のタグが無い
- [ ] ステージングの秘密の値が、本番用に用意する値と違う

## 5. 実機テスト

「確かめる」は、Claude Code が診断API（`/v1/admin/diagnostics`）で件数を読み、結果表に書きます。
オーナーはスマホの操作と、画面に出たものの確認だけで大丈夫です。

### テスト A: 広告から来て、その場で予約（iPhone）

1. Claude Code がテスト用の広告クリックを1件作り、入口のURL（`https://liff.line.me/<STG-入口>?ad_ref=<乱数>`）を渡します
   （gclid はテスト用の偽の値で、先頭を `TEST_` にします。先頭が `TEST_` の識別子は Worker が Google へ送りません）
2. そのURLを**テスト用のグループ**に貼り、スマホでタップする
3. 画面を確かめる
   - [ ] 初めてなら、LINE の同意画面が出る（友だち追加のチェックも出る）
   - [ ] 「LINEで予約へ進みます」と説明・ボタン2つが出る
4. 「**同意してLINEへ進む**」を押す
   - [ ] @nlx8658m の友だち追加（またはプロフィール）画面になる。**ここでは何も送らない**
5. テスト用のグループに戻り、`https://liff.line.me/<STG-フォーム>` を貼ってタップする
6. 名前「テスト」、電話番号はダミー（例: 090-0000-0000）、備考「テスト送信です」で送信する
   - [ ] 「予約内容を送信しました。」が出て、画面が閉じる
   - [ ] 予約希望メッセージが**テスト用のグループに**届いている（公式アカウントには届いていない）
7. 確かめる（Claude Code）: `bind_ok` 1件、`session_ok`、`inquiry_ok` 1件、区分 **`ad_same_day`** 1件、送信待ち 1件

### テスト B: 数日後に予約（同じ iPhone・2〜3日後）

1. 手順 A-5・A-6 をもう一度行う
2. 確かめる: 区分 **`ad_delayed`** 1件（送信待ちは「同じクリックの2件目」なので `suppressed_duplicate`）

### テスト C: 広告を通らない予約

1. 入口ページを通っていないアカウント（グループのもう1人など）で、A-5・A-6 だけを行う
2. 確かめる: 区分 **`none`** 1件、送信待ちは増えない

### テスト D: 同意しない

1. 新しい入口のURLをもらい、「**同意せずにLINEへ進む**」を押す
2. そのあと A-5・A-6 で送信する
3. 確かめる: `bind_ok` が増えない、区分 `none`

### テスト E: 送信してすぐ閉じる

1. A-6 の「予約内容を送信しました。」が出た瞬間に、LINE アプリごと閉じる
2. もう一度フォームを開く（送信はしない）
3. 確かめる: `inquiry_ok` か `inquiry_resent` のどちらかで、取りこぼしが無い

### テスト F: Worker が止まっていても予約できる

1. Claude Code がステージングの `AD_ATTR_ENABLED=false` にする
2. A-5・A-6 で送信する
3. 確かめる
   - [ ] 予約希望はグループに届き、画面も閉じる（いつもどおり）
   - [ ] 入口のURLを開くと、説明ではなく「LINEを開く」ボタンだけが出る
4. Claude Code が `true` に戻す

### テスト G: パソコンのブラウザで入口を開く

1. 入口のURLをパソコンのブラウザで開く
   - [ ] LINE のログイン画面が出て、ログイン後に入口ページへ戻る
   - [ ] 説明とボタンが出る

### テスト H: Android（あれば）

テスト A を Android で行う。

### テスト I: 友だち追加の前後

1. @nlx8658m を友だち追加していないアカウントで、テスト A を行う
   - [ ] 同意画面で友だち追加でき、あいさつメッセージはそのアカウントにだけ届く
   - [ ] 区分 `ad_same_day`
