# LINE 実機テストの手順書（OASIS本店・広告帰属）

自動テストでは確かめられない「LINE の中で本当に同じ人として結びつくか」を、スマホで確かめる手順です。
**本番の予約フォーム・本番の Worker・Wix・Google 広告には触りません。** テスト用の LIFF とステージングの Worker を使います。

所要時間の目安: 準備 60分（うち承認が要る作業あり）、テスト 40分、数日後の確認 10分。

## 2. テスト用の準備（承認が要る作業）

ここからは外部サービスの設定変更です。**オーナーの承認を得てから**行います。

### 2-1. ステージングの Worker（Claude Code が実施・Cloudflare）

- D1 `oasis-honten-attribution-staging` を作り、テーブルを作る
- Secret `ATTR_ROOT_KEY`・`ADMIN_TOKEN` を入れる（**Google の鍵は入れない**。送信はしない）
- `wrangler.jsonc` の staging に、1 で控えたチャネルIDを `LINE_CHANNEL_IDS` として入れる
- `AD_ATTR_ENABLED=true`、`UPLOAD_ENABLED=false` のままデプロイ
- 控える: ステージングの URL `https://oasis-honten-attribution-staging.<アカウント>.workers.dev`

### 2-2. テスト用のページ（Claude Code が実施・Cloudflare Pages など）

GitHub Pages は main しか出せないので、このブランチのページを**別の場所**に出します（本番のページは変えない）。

- `index.html`・`entry.html`・`css/`・`js/`・`img/` を写し、写しの中だけ次を書き換える
  - `js/liff-init.js` の LIFF ID → 2-3 で作る「STG-フォーム」の LIFF ID
  - `js/attribution-config.js` の `endpoint` → 2-1 の URL、`entryLiffId` → 「STG-入口」の LIFF ID
- 出した URL を控える: `https://______________/`（以下「テスト用のURL」）
- 2-1 の `FORM_ORIGINS` に、このテスト用のURLの Origin を足す

### 2-3. テスト用の LIFF を2つ追加（オーナー・LINE Developers）

**1 で開いたのと同じチャネル**に追加します（別のチャネル・別のプロバイダーだと、同じ人でも ID が変わり、テストになりません）。
既存の LIFF（`2006621786-8K7V4W3M`）は**変更しません**。

| STG-フォーム | テスト用のURL + `index.html` | 本番のフォームと**同じ**（1 で控えたもの） | 本番と同じ | 本番と同じ |

## 3. 実機テスト

各手順の「確かめる」は、Claude Code が診断API（`/v1/admin/diagnostics`）で件数を読み、結果表に書きます。
オーナーはスマホの操作と、画面に出たものの確認だけで大丈夫です。

### テスト A: 広告から来て、その場で予約（iPhone）

1. Claude Code がテスト用の広告クリックを1件登録し、入口のURLを渡します
   （`https://liff.line.me/<STG-入口>?ad_ref=<乱数>`。gclid はテスト用の偽の値で、Google には送りません）
2. そのURLを**自分の LINE**（Keep メモなど）に送り、スマホでタップする
3. 画面を確かめる
   - [ ] 初めてなら、LINE の同意画面が出る（友だち追加のチェックも出る）
   - [ ] 「LINEで予約へ進みます」と説明・ボタン2つが出る
4. 「**同意してLINEへ進む**」を押す
   - [ ] @nlx8658m の友だち追加（またはプロフィール）画面になる
5. @nlx8658m とのトークを開き、**自分で** `https://liff.line.me/<STG-フォーム>` と送信して、そのリンクをタップする
   （トークから開くと、本番のリッチメニューと同じく、そのトークへ送信できます）
6. 「2回目以降のお客様」または「初めての方」で進み、名前「テスト」、備考「テスト送信です」で送信する
   - [ ] 「予約内容を送信しました。」が出て、画面が閉じる
   - [ ] トークに予約希望メッセージが届いている
7. 確かめる（Claude Code）: `bind_ok` 1件、`session_ok`、`inquiry_ok` 1件、区分 **`ad_same_day`** 1件、送信待ち 1件

### テスト B: 数日後に予約（同じ iPhone・2〜3日後）

1. もう一度、手順 A-5 のリンクからフォームを開き、同じように送信する
2. 確かめる: 区分 **`ad_delayed`** 1件（送信待ちは「同じクリックの2件目」なので `suppressed_duplicate`）

### テスト C: 広告を通らない予約

1. 入口ページを通っていないアカウント（Android など）で、手順 A-5・A-6 だけを行う
2. 確かめる: 区分 **`none`** 1件、送信待ちは増えない

### テスト D: 同意しない

1. 新しい入口のURLをもらい、「**同意せずにLINEへ進む**」を押す
2. そのあと A-5・A-6 で送信する
3. 確かめる: `bind_ok` が増えない、区分 `none`

### テスト E: 送信してすぐ閉じる

1. A-6 の「予約内容を送信しました。」が出た瞬間に、LINE アプリごと閉じる
2. もう一度フォームを開く（送信はしない）
3. 確かめる: `inquiry_ok` か `inquiry_resent` のどちらかで、取りこぼしが無い

### テスト F: Worker が止まっていても予約できる

1. Claude Code がステージングの `AD_ATTR_ENABLED=false` にする
2. A-5・A-6 で送信する
3. 確かめる
   - [ ] 予約希望はトークに届き、画面も閉じる（いつもどおり）
   - [ ] 入口のURLを開くと、説明ではなく「LINEを開く」ボタンだけが出る
4. Claude Code が `true` に戻す

### テスト G: パソコンのブラウザで入口を開く

1. 入口のURLをパソコンのブラウザで開く
   - [ ] LINE のログイン画面が出て、ログイン後に入口ページへ戻る
   - [ ] 説明とボタンが出る

### テスト H: Android（あれば）

テスト A を Android で行う。

### テスト I: 友だち追加の前後

1. @nlx8658m を友だち追加していないアカウントで、テスト A を行う
   - [ ] 同意画面で友だち追加でき、そのあとトークで送信できる
   - [ ] 区分 `ad_same_day`
